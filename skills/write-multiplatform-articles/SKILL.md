# 一句话生成多平台运营文章矩阵

把一句产品简报扩展为有事实依据、平台适配明显、排版完备的可直接发布内容包。默认生成文章文件、发布配置表、标签、配图提示词并执行自动格式校验。

## 默认规则

- **默认语言**：简体中文。
- **默认覆盖平台**：知乎、掘金、微信公众号、CSDN、思否 (SegmentFault)、V2EX、简书、开源中国、InfoQ、腾讯云开发者社区、阿里云开发者社区、博客园等。
- **默认交付物**：
  1. `00-发布总表.md`：平台分工、文章标题、预期受众、发布标签、CTA 链接汇总。
  2. `[序号]-[平台名]-[文章标题].md`：各平台专属定制的正文（符合平台调性与排版）。
  3. `99-配图提示词.md`：封面图与正文信息图生成提示词（Midjourney/DALL-E 格式）。
  4. 校验脚本输出：运行 `scripts/validate_release.sh` 确保无缺失字段与占位符。

## 1. 解析输入简报

从一句话中提炼核心五要素：
1. **产品主体**：产品或开源项目名称。
2. **核心价值**：为谁解决什么关键痛点。
3. **目标动作**：了解、下载、试用、GitHub Star 或购买。
4. **已知事实**：支持平台、价格、技术栈（参考 `templates/product-fact-sheet.md`）。
5. **宣传红线**：严禁无根据声称“永久免费”、“绝对安全”、“全网第一”。

## 2. 平台调性差异化适配

| 平台类别 | 核心平台 | 语言风格与排版要求 |
| :--- | :--- | :--- |
| **极客与程序员社区** | V2EX、掘金、思否、开源中国 | 代码优先、架构原理解析、实事求是。严禁空洞煽情；写清踩坑与性能测试数据。 |
| **深度知识与问答** | 知乎 | 结构化问答风（“如何评价...”、“怎样高效解决...”），逻辑严密，图文穿插。 |
| **新媒体与私域流量**| 微信公众平台 | 故事化开篇、短段落、排版美观，强调情绪共鸣与实际生产力提升。 |
| **技术博客与开发者**| CSDN、博客园、各大云社区 | SEO 友好、步骤清晰的实战教程（Step-by-step）、常见报错与解决方案。 |

## 3. 输出与自检

生成完成后，运行发布包自动化校验：
```bash
./scripts/validate_release.sh ./output_dir [预期篇数] [官网/仓库链接]
```
检查是否存在占位符（TODO/待确认）、是否包含唯一的 H1 标题、结尾链接是否符合标准。
